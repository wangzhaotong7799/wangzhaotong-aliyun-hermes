# 📄 报告排版美化规范 v1.0

> **核心原则**: 内容决定价值，排版决定阅读体验。一份好报告，排版必须配得上内容的深度。

---

## 一、Markdown 排版规范

### 1.1 层级结构
```
# 报告标题（仅1个一级标题）
## 章节标题（数字序号+中文）
### 小节标题（阿拉伯数字）
#### 段落标题（可选，尽量避免）
```

- **一级标题**: 全报告仅1个，居中或左对齐。含报告名称+日期
- **二级标题**: 每个独立板块，建议用编号 `## 一、xx`、`## 二、xx`
- **三级标题**: 子板块，`### x.x xx`
- **禁止** 超过4级标题嵌套

### 1.2 核心元素排版标准

| 元素 | 规范要求 |
|------|---------|
| **引言/摘要** | 放在一级标题后，用块引用 `>` 包裹，简短精炼 |
| **执行摘要** | 用 `┌──┐` box-drawing 围起来，或块引用+粗体 |
| **核心结论** | 编号列表 + 加粗关键词 |
| **数据表格** | 至少3行，头部加粗，左对齐 |
| **评分矩阵** | 必须加权计算，分数突出显示 |
| **代码块** | 仅用于命令示例，短小精悍 |
| **对比表格** | 用 `---` 分隔线+表头格式 |
| **风险/警告** | 用 `⚠️` 或 `> **警告**` 格式 |
| **数据来源** | 附录统一管理，编号 + URL |

### 1.3 表格排版要点

```markdown
| 左对齐 | 居中 | 右对齐 |
|:-------|:----:|-------:|
```

- 表头加粗，首行大写
- 数字列右对齐，文字列左对齐
- 关键数字高亮（加粗或用 `**数字**`）
- 每列宽度要均匀，不要一列长一列短
- 表前空行，表后空行

### 1.4 Box-drawing 增强

用于突出核心结论和关键数据块：

```
┌─────────────────────────────────────┐
│  核心结论标题                        │
│                                     │
│  📌 要点1：xxxx                      │
│  📌 要点2：xxxx                      │
└─────────────────────────────────────┘
```

**规范**：
- 外框用 `┌ ┐ └ ┘ ─ │`
- 标注符号统一用 `📌`、`🔥`、`⚠️`、`✅`、`❌`、`🎯`
- 框内缩进2空格，总宽度不超过80字符
- 用于：执行摘要、核心发现、风险提示

### 1.5 评分矩阵排版

```markdown
| 评分维度 | 权重 | 赛道A | 赛道B | 赛道C |
|:---------|:---:|:-----:|:-----:|:-----:|
| 市场规模 | 20% | 8/10  | 6/10  | 7/10  |
| 增速     | 20% | 7/10  | 9/10  | 8/10  |
| **加权总分** | 100% | **7.5** | **6.4** | **7.1** |
```

- 最后一行加总分，粗体高亮
- 权重列居中，分数列居中
- 加粗最佳分数

## 二、Word 文档排版规范

### 2.1 工具选择（按优先级）

| 工具 | 推荐场景 | 安装状态 |
|------|---------|---------|
| **md2word** | Markdown→Word快速转换，中文友好 | ✅ 已安装 |
| **python-docx** | 需要精细控制的场景 | ✅ 已安装 |
| **python-docx-template** | 有预置模板时的批量生成 | ⚠️ 可选 |

### 2.2 md2word 配置规范

配置文件位于: `scripts/md2word_config.json`

**关键配置项**：

| 配置 | 推荐值 | 说明 |
|------|--------|------|
| 正文字体 | 微软雅黑 | 中英文混排最佳选择 |
| 标题颜色 | #1A365D (深蓝) | 专业稳重 |
| 二级标题 | #2B6CB0 (蓝) | 清晰层次 |
| 行距 | 1.35倍 | 舒适阅读 |
| 表格表头 | 深蓝底+白字 | 清晰区分 |
| 表格行交替色 | #F7FAFC (浅灰) | 提高可读性 |
| 引用块 | 蓝左边框+浅蓝底 | 突出引用 |

### 2.3 使用命令

```bash
# 标准转换（带目录）
cd /path/to/wealth-analyst/data
/root/.hermes/hermes-agent/venv/bin/python3 -m md2word report.md \
  -c scripts/md2word_config.json --toc -o report.docx

# 快速转换（无目录）
/root/.hermes/hermes-agent/venv/bin/python3 -m md2word report.md -o report.docx
```

### 2.4 校验清单（交付前自检）

```
□ 报告标题完整（含日期/数据年份）
□ 层级不超过4级
□ 表头对齐正确
□ 评分矩阵有加权总分
□ 所有数据注明来源
□ 附录有数据来源列表
□ 风险提示有标注
□ Word文档字体正确
□ Word表格交替行颜色
□ Word有目录（长报告）
□ 中文字体使用微软雅黑
□ 飞书摘要提炼了核心结论
```

## 三、报告结构模板

### 3.1 完整报告结构

```markdown
# 📊 报告标题（含日期）

> 报告概述：一句话说清楚这份报告做什么

---

## 一、执行摘要

┌── 核心结论框 ──┐
│ 结论1           │
│ 结论2           │
└────────────────┘

## 二、[赛道A]深度分析

### 2.1 市场规模
### 2.2 竞争格局
### 2.3 增长驱动
### 2.4 风险提示

## 三、[赛道B]深度分析

(同上结构)

## 四、赛道评分矩阵

| 维度 | 权重 | A | B | C |
|-----|:---:|:-:|:-:|:-:|
| **总分** | | **7.5** | **6.4** | **7.1** |

## 五、策略建议

### 5.1 优先级一：xxx
### 5.2 优先级二：xxx
### 5.3 谨慎入局：xxx

## 六、附录：数据来源

| # | 来源 | URL | 类型 |
|---|------|-----|------|
```

### 3.2 精简报告结构（飞书摘要版）

```markdown
📊 标题

📌 核心结论：
• 结论1
• 结论2

🏆 评分Top3：
1️⃣ xxx — 说明
2️⃣ xxx — 说明

⚠️ 风险提示：
• 风险1
• 风险2

详情见附件Word报告
```

## 四、飞书消息排版规范

| 元素 | 格式 | 说明 |
|------|------|------|
| 标题行 | `📊 标题` | emoji + 文字 |
| 分隔 | `—` 或 `---` | 段落间分隔 |
| 列表 | `•` 或 `1️⃣ 2️⃣ 3️⃣` | 简洁要点 |
| 关键数字 | **加粗** | 数字突出 |
| 评分排名 | 🥇🥈🥉 | 一目了然 |
| 风险警告 | ⚠️ | 警示 |
| 链接 | `[文字](URL)` | 可点 |

## 五、自我审查

生成报告后，在交付前问自己：

1. **结构清晰吗？** — 读者能不能30秒内找到核心结论？
2. **排版专业吗？** — 表格对齐、颜色统一、字体一致？
3. **数据可信吗？** — 每条关键数据都有来源标注？
4. **Word漂亮吗？** — 表头有颜色、行有交替色、字体正确？
5. **飞书摘要精炼吗？** — 核心结论+评分+风险，不超5句话？
