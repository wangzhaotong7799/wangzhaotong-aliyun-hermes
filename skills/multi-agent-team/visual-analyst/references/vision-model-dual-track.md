# 视觉模型双轨架构

## 设计目标

日常看图省钱，帧分析保证质量，互不影响。

## 配置方案

```
┌────────────────────────────────────────────────────────────┐
│                    Hermes 视觉模型双轨                        │
├──────────────────────┬─────────────────────────────────────┤
│   日常看图（轻量）    │     帧分析（最高画质）                  │
├──────────────────────┼─────────────────────────────────────┤
│   qwen3-vl-plus      │     qwen-vl-max-2025-08-13          │
│   全局 vision_analyze│     batch_analyze.py 直调百炼 API    │
│   通过 config.yaml 配 │     通过脚本默认模型配                │
│   auxiliary.vision   │     VISION_MODEL 环境变量可覆盖       │
├──────────────────────┼─────────────────────────────────────┤
│   适用：截图、文档、   │   适用：逐帧视频分析、产品细节、         │
│   快速图文识别        │   色彩/照明/构图深度分析               │
└──────────────────────┴─────────────────────────────────────┘
```

## 为什么不只用全局配置？

全局 `vision_analyze` 工具只能指定一个模型。如果设为 qwen-vl-max：
- 日常截图也走最高画质 → 浪费钱

如果设为 qwen3-vl-plus：
- 帧分析质量不够 → 影响视频提示词质量

所以帧分析场景绕过全局工具，通过脚本直调 API 并指定更贵的模型。

## 调用方式对比

| 场景 | 调用方式 | 模型 | 费用 |
|:----|:--------|:----|:----:|
| 日常看图 | `vision_analyze(image_url=...)` 工具 | qwen3-vl-plus | 低 |
| 帧分析 | `batch_analyze.py` 脚本 | qwen-vl-max | 高（合理） |

## 关键文件

| 文件 | 作用 |
|:----|:----|
| `config.yaml` → `auxiliary.vision.model` | 全局 vision 模型 |
| `scripts/batch_analyze.py` | 帧分析脚本，默认使用 qwen-vl-max |
| `SKILL.md` — 备选方案章节 | 说明何时用哪种方式 |

## 注意事项

- `batch_analyze.py` 通过环境变量 `VISION_MODEL` 可覆盖默认模型
- 显式设置 `VISION_MODEL=qwen3-vl-plus` 可临时切回便宜模型做测试
- 选帧质量要求极高时才需要用 max，大部分场景 plus 够用
