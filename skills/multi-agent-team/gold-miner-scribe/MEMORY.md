## 二、报告模板（各域章节结构速查）

### 自媒体域（6章标配）
```
1. 总览摘要（300字以内，box-drawing 核心结论框）
2. 各赛道赚钱潜力排行（评分矩阵：加权总分+排名）
3. 六大平台政策解读与机会点（抖音/小红书/B站/视频号/快手/TikTok）
4. 典型案例分析（成功+失败）
5. 分阶段执行路线图（30/60/90天）
6. 风险提示与避坑指南
附录：资料来源标注
```

### 电商域（6章）
```
1. 总览摘要 + 核心结论
2. 电商赛道赚钱潜力排行（评分矩阵表）
3. 各平台政策与机会点（淘宝/京东/拼多多/抖音/快手/TikTok Shop/TEMU）
4. 典型案例（成功+失败）
5. 分阶段执行路线图（30/60/90天）
6. 风险提示（流量成本、平台抽成、关税政策、合规红线）
附录：资料来源标注
```

### CPS联盟营销域（6章）
```
1. 摘要 + 核心结论 — 6赛道横向对比总览
2. 赛道赚钱潜力排行（评分矩阵表，含佣金率实测估算）
3. 各平台CPS政策对比（佣金比例/规则/准入条件）
4. 案例池 — 成功 + 失败（政策封禁、佣金断崖式下调、微信生态收紧）
5. 入局路线图（按资源禀赋分三档：个人→小团队→机构）
6. 风险清单（平台抽成下调、封号、反垄断、微信生态收紧）
附录：资料来源标注
```

### 其他域（4章通用）
```
1. 总览摘要（核心结论2-3条）
2. 赛道排行评分矩阵
3. 关键平台/渠道分析
4. 风险与机会
附录：资料来源标注
```

## 三、写作规范（v2.0 强化）

- **排版规范必加载**：写报告前先 `skill_view(name='beautiful-report-formatting')`，box-drawing 核心框 + 评分矩阵加权高亮 + 表格对齐 + 层级≤4级
- 每个数据点后面跟着 `[来源: URL/说明]`
- 数据不足处使用 `[需人工调研]` 标记
- 风险提示前加 `⚠️` 符号
- 成功和失败案例必须各至少 2 个
- 摘要不超过 300 字
- 每条赛道必须有"建议"列（进入/观望/放弃）
- 各赛道数据标注年份范围（例："本赛道数据基于2026年1-5月公开信息"）
- **双版本输出**（Cron 默认）：完整版→`data/report_YYYYMM.md`（300-500行）+ 精简版→final response（50-80行：评分排行表+Top3+一句话总结）

## 四、经验记录（2026-08-10 更新）

- **行数经验值（实测）**：全委托模式 250-350行/10赛道约17KB；联合手动模式 180-220行/11-13KB（内容完整度不受影响，不要为凑行数硬灌）；精简版 50-80行
- **双版本缺一不可**：只写完整版不写精简版→飞书推送超长截断；只写精简版→用户拿不到完整 Word 附件
- **飞书表格可能渲染不全**：评分表在飞书消息中可能不显示，重要排行数据由猎财 send_message 单独补发，报告内表格仅作附录参考
- **md_to_feishu_docx.py 用 Hermes venv Python 调用**：`/root/.hermes/hermes-agent/venv/bin/python3`，不用系统 python3
- **Cron 交付冲突**：cron prompt 中若出现 `DELIVERY:` 标记，报告以 final response 形式自动投递，跳过飞书手动步骤
