## 一、按域名/平台的 URL 年份模式

| 域名 | 年份编码方式 | 正则模式 | 示例 | 可靠性 |
|:----|:-----------|:--------|:-----|:------|
| **people.com.cn** | URL路径带日期 | `/n1/2026/0514/c1004-...` | ✅ 高 |
| **news.qq.com** | URL路径带日期 | `/rain/a/20260407A04R...` | ✅ 高 |
| **sina.com.cn** | URL路径带日期 | `/2026-05-19/doc-...` | ✅ 高 |
| **163.com/dy/** | 路径无日期，需从页面内容提取 | — | ⚠️ 中 |
| **36kr.com** | 文章ID区间推断 | `/p/3780189195949060` | ⚠️ 启发式 |
| **tmtpost.com** | 路径无日期，文章内有时间戳 | `/7999440.html` | ⚠️ 中 |

| **bilibili.com** | 页面发布时间戳 | `/opus/1210433710879...` | ⚠️ 中 |
| **chinairn.com** | URL路径带日期 | `/news/20260525/170938...` | ✅ 高 |

## 二、36kr URL ID 区间启发式（需交叉验证）

36氪不对外暴露显式日期，但文章ID（URL中的纯数字段）与年代有相关性：

| ID 区间 | 推定年代 | 置信度 |
|:-------|:--------|:------:|
| 38xxxxxx ~ 37xxxxxx | 2026年 | 高 |
| 37xxxxxx ~ 33xxxxxx | 2025年 | 中高 |
| 33xxxxxx ~ 28xxxxxx | 2024年 | 中 |
| 28xxxxxx ~ 20xxxxxx | 2023年 | 中低 |
| 20xxxxxx ~ 17xxxxxx | 2020-2022年 | 中低 |
| < 17xxxxxx | 2019年及以前 | 中 |

**局限性**：ID并非线性对应日期，同一区间内可能跨年。**始终优先用web_extract确认**有疑问的36kr文章。

## 三、标题/内容中的年份关键词优先级

| 信号 | 示例 | 优先级 | 说明 |
|:----|:-----|:------|:-----|
| URL含/2026/ | `people.com.cn/n1/2026/...` | 最高 | 直接明确 |
| 标题含"2026" | "2026短剧行业十大趋势" | 高 | 行业报告多为当年发布 |
| 发布时间戳 | "2026.05.22 23:35" | 高 | 正文开头 |
| 正文含"2026年" | "2026年1月，知识类短视频..." | 中高 | 需注意回忆性文章 |
| 标题含"2025" | "2025年回顾" | ❌ | 明确旧数据 |
| 无任何年份信号 | — | ⚠️ | 建议web_extract确认 |

## 四、已知的"易误判"场景

1. **展望性文章**：标题"2026年十大趋势"发布于2025年末 → 正文含"2025年12月"信号 → 综合判定
2. **年度回顾文章**：2026年刊发的"2025年行业回顾" → URL含2026 + 正文多2025 → URL优先
3. **跨年报告**："2025-2026年行业报告" → 标题同时含两个年份 → 按URL路径年份判定
4. **行业报告PDF**：智研咨询/中研普华等报告商 → URL路径日期可靠
5. **转载文章**：36kr转载其他来源 → 以36kr的发布ID为准（而非原出处年份）
