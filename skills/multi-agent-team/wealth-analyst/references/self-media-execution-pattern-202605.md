## 二、数据采集模式

### 搜索策略

```
第1轮 — 赛道宽搜索（8次，并行）
  搜索词模板: "2026年 [赛道] 自媒体 [平台1] [平台2] 变现 趋势"
  示例: "2026年 短剧 市场 规模 抖音 快手 小红书 趋势"
  每个赛道搜索1次，limit=10

第2轮 — 平台政策搜索（4次，并行）
  搜索词: "2026年 [平台] 创作者 收入 变现 分成 政策 调整"
  覆盖：抖音、小红书、B站、视频号
  注意：快手和TikTok各搜索1次补充即可

第3轮 — 失败案例搜索（2次）
  搜索词: 
    - "短剧 亏本 制作公司 倒闭 2026 红果 政策 转型"
    - "自媒体 MCN 倒闭 亏损 2026 达人 收入下降 停更"

可选第4轮 — 排行/蓝海搜索（1次）
  搜索词: "2026年 自媒体 赚钱 赛道 排行 变现效率 蓝海 红利"
```

### 搜索结果处理

- 每次搜索返回10条结果，选择信息密度高的3-5条详细提取
- 对关键文章使用 `web_extract` 提取全文（如腾讯新闻·红果虚假繁荣一文极其有价值）
- 知乎专栏经常需要登录 → 不要依赖知乎内容
- 36氪、新浪财经、腾讯新闻、虎嗅的内容质量最高

### 数据年份标注规则

| 字段 | 提取方式 | 示例 |
|:-----|:---------|:-----|
| data_year | 从URL/标题/描述中提取的年份 | 2026 |
| source_publish_date | 文章发布日期（在搜索结果中往往不可直接获取） | 2026-05 |
| collected_at | 实际采集时间 | 2026-05-11 |

## 六、SILENT 模式判断

对于每周执行的定时Cron任务，如果本周数据与上周相比无明显变化（无重大行业事件、无平台政策变更、无格局变化），可以考虑输出 `[SILENT]` 抑制投递。

**判断标准**（至少满足2条才投递）：
1. 有至少1个赛道出现了新的关键数据/市场份额变化
2. 至少1个平台发布了新的创作者政策
3. 有新的失败案例/行业事件
4. 评分排行相比上周有变化（≥0.3分的变动）

### 7.5 流程改进建议

1. **truncate=1200已是Exa搜索通过率保障线**：136条→108条（79.4%）的通过率虽低于92%的最佳记录，但每个赛道仍有≥5条有效数据，已满足进入评分条件。无需为追求通过率而追加第二轮搜索。

2. **年份验证闸门中的标题-年份矛盾需人工核实**：本轮出现1条疑似篡改（URL含2025但标题提到2026），经核实是文章讨论2026规划但发表于2025——正确标注data_year=2025，不是篡改。该记录已被自动剔除。闸门脚本标记的"疑似篡改"需人工复核后再决定是否中断流程。

3. **手动模式报告380行/24KB符合预期**：8赛道×5节（数据表+分析+策略+LTV+风险）+ 6平台政策 + 失败案例 + 路线图 = 可达300-400行。手动模式写报告时不需追求delegation模式的500行，内容完整即可。

4. **⚠️ 必须先加载 beautiful-report-formatting**：本次执行中该步骤被跳过（未加载即写报告），虽然最终输出结构完整（含 box-drawing 核心框、评分矩阵加权行、表格对齐），但应养成先加载再写报告的纪律。详见 wealth-analyst SKILL.md 阶段五。
