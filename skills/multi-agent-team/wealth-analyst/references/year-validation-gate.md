# 年份验证闸门操作手册

> 归属：猎财SOP 阶段三 — 质量关键控制点
> 版本：v1.0 | 创建：2026-05-04

---

## 一、闸门触发条件

每次天网（gold-miner-sky）采集数据返回后，在**数据传入算盘评分之前**，猎财必须执行本闸门。**此步骤不可跳过。**

## 二、核心原则

| 原则 | 说明 |
|:---|:---|
| 年份原始性 | 数据中的年份信息必须来自来源文章的真实发布日期，禁止根据采集时间反向推断 |
| 信任来源 > 信任AI | `source_publish_date`（发布日期）优先级高于 `collected_at`（采集时间） |
| 宁缺毋滥 | 数据不足时标注"置信度低"而非伪造数据源 |
| 发现即中断 | 确凿篡改证据时立即终止全流程 |

## 三、逐条检查流程

### Step 1: 提取年份

每条天网数据应有如下字段：

```json
{
  "title": "2026年电商趋势报告",
  "source_publish_date": "2026-04-15",
  "data_year": 2026,
  "collected_at": "2026-05-04T10:30:00Z",
  "url": "https://...",
  "content": "..."
}
```

**字段优先级**：
1. `data_year` — 天网已提取的年份（如有）
2. `source_publish_date` — 原始发布日期
3. 正文中首个出现的年份信息（备选，需标注为"推测"）

### Step 2: 年份判定

| data_year | 判定结果 |
|:---|---:|
| 2026 | ✅ 通过 |
| 2025 | ❌ 剔除（标注"2025年旧数据"） |
| 2024 或更早 | ❌ 剔除（标注"YYYY年旧数据"） |
| 无日期信息 | ❌ 剔除（标注"无发布日期"） |

### Step 3: 篡改检测

检查以下异常模式：

| 异常模式 | 检测方法 | 处理方式 |
|:---|:---|:---|
| `collected_at=2026` 但文章内容明显提及"2024年" | 扫描正文年份关键词 | 标记"疑似篡改"，保留记录 |
| `source_publish_date` 缺失但正文有年份 | 对比正文年份与采集年份 | 标记"年份不完整" |
| 标题含"2024年"但标注 `data_year=2026` | 标题文本分析 | 标记"标题-年份矛盾" |
| 多条记录来自同一来源但日期矛盾 | 按来源URL去重比对 | 标记"来源日期不一致" |

**发现确凿篡改（如标题写2024、内容写2024、但强行标注2026）→ 立即中断全流程，向用户报告。**

## 四、质量报告格式

写入 `data/quality_gate_report.md`:

```markdown
# 数据质量报告 — [域名称] — YYYY年MM月

## 采集概况
- 总采集记录：N条
- 通过年份验证（≥2026年）：N条（XX.X%）
- 已剔除：N条（XX.X%）
  - 2025年数据：N条
  - 2024年及更早数据：N条
  - 无发布日期标注：N条
- 疑似篡改检出：N条（如>0需中断流程）

## 赛道覆盖情况
| 赛道 | 有效数据条数 | 覆盖评估 |
|:---|:---:|:---:|
| 赛道A | N | ✅ 充分 |
| 赛道B | N | ⚠️ 偏少 |
| 赛道C | N | ❌ 严重不足 |

## 违规记录
- 无篡改年份痕迹
```

## 五、通过/中止标准

| 条件 | 行动 |
|:---|:---|
| 每个赛道 ≥ 5条有效数据 | ✅ 进入阶段四（算盘评分） |
| 某赛道 3-4条有效数据 | ⚠️ 评分时标注"数据置信度低" |
| 某赛道 < 3条有效数据 | ❌ 标注"严重不足，建议人工调研" |
| 半数以上赛道 < 3条有效数据 | 🚫 终止流程，向用户报告"2026年公开数据严重不足" |
| 发现 ≥ 1条确凿篡改 | 🚫 终止流程，立即向用户通报 |

## 六、常见错误模式

### 模式A：AI自作聪明补年份
**问题**：天网采集到的数据没有明确发布日期，AI自动填入 `collected_at` 的年份作为 `data_year`。
**对策**：无 `source_publish_date` 的数据直接归入"无发布日期"类别并剔除。严禁AI脑补。

### 模式B：标题中的年份误读
**问题**：文章标题是"回顾2024，展望2025"，AI提取了2024作为data_year，但文章实际发布于2026年。
**对策**：优先使用 `source_publish_date`（文章的元数据发布日期）。标题中的年份仅作辅助参考。

### 模式C：榜单/排行榜数据无年份
**问题**：抖音热榜、小红书热门等实时榜单数据没有明确的"发布日期"。
**对策**：此类数据以 `collected_at` 的年份为准，但需在备注中标注"榜单数据，采集日期=发布日期"。

### 模式D：行业报告PDF/文章发表时间久远
**问题**：火了很多年的行业报告（如"电商行业蓝皮书"）可能2024年有版本，2026年有新版。
**对策**：优先搜索2026年版。如果只能找到2025年版本，标注数据年份为2025，进入剔除流程。报告正文注明"该赛道2026年版本尚未发布"。
